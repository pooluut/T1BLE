# Domain Docs

本仓库采用 single-context 领域文档布局。

## 探索代码前

- 阅读根目录的 `GLOSSARY.md`（如果存在）。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策记录。

文件或目录尚不存在时，直接继续工作。
领域术语或决策得到明确结论后，再由 domain-modeling
按需创建文档。

## 文档位置

- `GLOSSARY.md`：本仓库统一的领域术语表。
- `docs/adr/NNNN-<decision-slug>.md`：架构决策记录。

## 使用领域术语

在任务标题、设计建议、假设和测试名称中，
使用术语表定义的名称，遵循其中的同义词约定。

需要的概念尚未定义时，先检查现有领域语言是否能表达；
确有缺口时，记录为后续 domain-modeling 的输入。

## 架构决策冲突

建议与现有 ADR 冲突时，明确指出对应 ADR、
冲突内容，以及建议重新讨论该决策的原因。
