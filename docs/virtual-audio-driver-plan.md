# Virtual Audio Driver 接入方案与源码核验

核验日期：2026-11-12。

## 用户指定方向

使用 VirtualDrivers/Virtual-Audio-Driver 作为虚拟音频设备基础；
参考 Belphemur/SoundSwitch 的音频设备管理和切换逻辑。
保留 C# 应用、ATVV 1.0 采音、搜索键拦截；不增加按键防抖和触发等待。

## 已核验事实

### 驱动

- 仓库：https://github.com/VirtualDrivers/Virtual-Audio-Driver
- 核验提交：`bb34fba15faf569a6ae9bdea360bc1cf4821354e`。
- 许可证：MIT，另需遵守源码包含的第三方声明。
- `Source/Main/minwavertstream.cpp` 的 `CMiniportWaveRTStream::WriteBytes`
  对录音 DMA 缓冲区执行 `RtlZeroMemory`，向录音客户端提供静音。
- 同文件 `ReadBytes` 将播放数据交给 `m_SaveData.WriteData`。
  当前核验的播放/录音路径没有实现二者之间的音频桥接。
- README 将命名管道、共享内存等集成方式描述为定制构建功能，
  不能假设公开发行包具备这些接口。
- latest release API 返回 `25.7.14`，资产名称带 Signed；
  README 同时提示 beta 和测试签名。资产名称不足以证明本机安装信任链，
  应核验实际驱动包签名和 Windows 加载结果，而不是默认修改启动签名设置。
- 本机本次枚举没有发现该项目的虚拟音频设备。

### SoundSwitch

- 仓库：https://github.com/Belphemur/SoundSwitch （dev 分支）。
- 许可证：GPL-3.0；若直接采用其代码，应评估整个组合与分发方式的许可证义务。
  当前只参考设计，不将源码复制到项目中。
- `SoundSwitch.Audio.Manager/AudioSwitcher.cs` 展示设备 ID、默认设备角色、
  COM 专用线程、设备通知、音频服务异常处理，以及进程级路由管理。
- 切换系统默认录音设备与选择虚拟麦克风内部音源是不同层次。
  系统设备切换不能代替驱动音频数据通路。

## 推荐的数据通路

```text
物理麦克风 → C# WASAPI 采集 ─┐
                            ├→ 应用内部音源选择 → WASAPI 虚拟播放端
遥控器 BLE → ADPCM 解码 ─────┘                         ↓
                                  驱动共享环形缓冲 → 虚拟录音端 → Win+H
```

优先扩展驱动为播放端到录音端的桥接，复用标准 WASAPI 写入；
暂不额外引入自定义 IOCTL 或共享内存 ABI。
此图为目标架构，不代表上游已具备该功能。

## 必须先补齐的驱动工作

1. 明确一对播放/录音端点及统一内部 PCM 格式。
2. 在适当的设备共享上下文中实现有界环形缓冲，连接 render 消费路径和 capture 填充路径。
3. 确定读写同步、溢出丢弃策略、欠载补零、时钟漂移、格式变化与多客户端行为。
   不在实时内核路径执行阻塞 I/O 或动态分配。
4. 处理暂停、重置、设备关闭和电源状态转换，避免重放上次会话残留。
5. 配置 WDK/C++ 构建与签名流程。现有 .NET SDK 只能编译 C#，不能独立构建该内核驱动。
6. 先用已知信号证明播放到录音的通路，再接入实际麦克风与遥控器。

## C# 应用职责

- 根据持久设备 ID 选择真实麦克风与虚拟端点，显示名称只用于 UI。
- 使用持续运行的音频输出，默认转发真实麦克风。
- 遥控器 AUDIO_START 后切换音源，停止、断连或失败后恢复真实麦克风。
- 将各来源转换到统一输出格式；切换时丢弃旧音源积压，禁止两路同时送出。
- 音频桥接的生命周期独立于 BLE 连接和诊断会话；遥控器休眠不终止电脑麦克风桥接。
- 参考 SoundSwitch 的专用 COM 线程和设备通知机制，支持拔插与默认设备变更。
- 系统默认输入可固定为虚拟麦克风；系统级切换只用于设置和故障恢复，
  不是每次遥控器按键必须执行的步骤。
- 正常退出时，若默认设备仍是程序设置的虚拟麦克风，恢复原有输入；
  用户中途手动变更时尊重用户的新选择。异常退出后的恢复另需可验证机制。

## 完成标准

- 已知信号写入虚拟播放端后，虚拟录音端能收到对应波形，不能只验证非静音。
- 遥控器休眠时电脑麦克风仍能通过虚拟录音端用于 Win+H。
- 遥控器启动/停止时源切换正确，不重复收音，不重放积压。
- 设备断连、音频服务重启、应用退出后的行为经实测。
- 搜索键不会抢走输入焦点，键盘 Win+H 与遥控器输入都能独立工作。
